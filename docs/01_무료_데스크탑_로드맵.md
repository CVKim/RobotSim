## T1. ToF 대차 인식 기술 리포트 — 보유 데이터가 재료 (3–4 주말)

이미 갖고 있는 현장 RGB+ToF 이미지(빈피킹·대차)만으로 완결. GPU 부담 거의 없음.

**1단계 — 박스 인스턴스 분할 벤치마크**
- 이미지 200~500장 선별 → CVAT(로컬 Docker로 구동 가능, 무료)로 박스 인스턴스 라벨링
- 비교 3종:
  - (a) Grounded-SAM-2 zero-shot — 텍스트 프롬프트 "cardboard box", "cart" (WSL2 권장, CUDA op 컴파일 필요)
  - (b) SAM2.1 small/base+ visual prompt (10GB 안전권; large는 ~10GB 소모 보고 있어 비권장)
  - (c) SCD(Stacked Carton Dataset, 25만 마스크 — 적재 카톤 전용 공개 데이터셋)로 사전학습한 YOLO11-seg 또는 Mask2Former를 자기 데이터로 파인튜닝
- 산출: mAP 비교표 + 실패 사례 분석(랩 필름 반사, 저조도 등)

**2단계 — 박스 치수 측정 (parcel dimensioning)**
- 분할 마스크로 ToF 포인트클라우드 크롭 → Open3D: RANSAC 지배 평면 + minimal oriented bounding box → L×W×H
- 평가: 줄자 실측 GT 대비 **mm 오차를 거리별·재질별(골판지/랩필름/금속 프레임)** 리포트
- 프레이밍: Zebra가 법정거래(NTEP/OIML) 인증까지 받아 파는 실제 제품 카테고리 — "±mm 정확도 스펙" 제품 언어로 결과 기술
- 딥러닝은 분할에만, 치수는 기하로 푸는 것이 산업 표준 구조

**3단계 — 적재율(fill-rate) 추정기**
- 대차 내부 볼륨 기준 복셀 점유율, 또는 Zebra 특허(US10657666)의 depth-histogram "package wall" 방식
- 적재 과정 시계열 시각화. GPU 불필요 수준

**보너스 챕터 — ToF 실측 vs 2025 monocular depth 파운데이션 모델**
- Depth Anything V2/DA3-Small, UniDepthV2, Metric3D v2, MoGe-2, Depth Pro — 전부 10GB 추론 OK
- 자기 RGB에 추론 → ToF 실측 대비 AbsRel/RMSE를 재질·거리별 비교
- **PromptDA**(Prompt Depth Anything, CVPR 2025, Apache-2.0, Small 25M): 저해상도 ToF depth를 프롬프트로 넣어 고해상도 metric depth 생성 — 보유 데이터 구성(RGB+저해상 ToF)과 정확히 일치하는 모델. flying pixel 제거·경계 개선 정량화

**산출물(로컬)**: 기술 리포트 md/pdf + 재현 코드. → 공개 여부는 `03_공개전략_및_데이터보안.md` 참조 (공장 데이터 보안 주의!)

## T2. LeRobot 시뮬 모방학습 부트캠프 — 하드웨어 없이 전체 파이프라인 체득 (1–2 주말)

LeRobot(HF의 로봇 학습 표준 라이브러리, v0.6.x)의 데이터셋 v3 → 학습 → 평가 루프를 시뮬로 완주.

1. 네이티브 Windows에 `lerobot[training]` 설치 (Python ≥3.12, CUDA torch) — `02_환경_셋업.md` 참조
2. **PushT + Diffusion Policy**: 공개 데이터셋으로 학습(BS4 + gradient checkpointing으로 10GB OK) → eval 영상
3. **gym-aloha + ACT**: ACT는 2–6GB라 여유. 50 에피소드급 학습이 3080에서 ~1시간
4. **SmolVLA-450M 파인튜닝 맛보기**: `lerobot/smolvla_base`를 공개 SO-101 데이터셋(`lerobot/svla_so101_pickplace`)으로 파인튜닝 — BS2–4 + `freeze_vision_encoder=true` + grad accumulation으로 10GB 내
5. 두 번째 3080 활용: WSL2에서 `accelerate launch --num_processes=2` DDP(Windows는 NCCL 없음), 또는 네이티브에선 시드 2개 병렬 실험

**의미**: "π0/GR00T는 24–40GB라 로컬 불가, 그래서 SmolVLA를 골랐다"를 실행 경험으로 말할 수 있게 됨.
대형 VLA가 꼭 필요해지면 그때 HF Jobs(`--job.target=a10g-large`, 초 단위 과금)로 1회성 — 지금은 불필요.

## T3. gym-hil HIL-SERL — 실로봇 없는 실전급 강화학습 (1 주말 + α)

Berkeley HIL-SERL(Science Robotics 2025)의 LeRobot 공식 통합판을 **MuJoCo 가상 Franka**로 완주.

- `gym-hil`: HIL-SERL 연습 전용으로 만들어진 시뮬 환경 (pick-cube 등)
- 워크플로: 데모 수집(키보드/게임패드) → ROI crop 128×128 → ResNet10 reward classifier 학습 → gRPC actor/learner SAC → 사람 개입 → **개입률 감소 곡선**
- 인간 개입 포함 시 시뮬 정책이 **~10–30분 만에** 수렴 — 첫 강화학습 포트폴리오 플롯
- **네이티브 Windows에서 실행** (MuJoCo+PyTorch 스택; 게임패드 USB를 WSL2로 포워딩하는 삽질 금지)
- 2-GPU: learner GPU0 / actor GPU1 프로세스 분리 실습 가능
- 집에 게임패드 없으면 키보드 개입으로도 가능 (게임패드는 2~3만원짜리면 충분, 필수 아님)

**심화(선택)**: 같은 데이터로 BC 정책을 만들고 그 위에 ResFiT 스타일 **residual RL**(작은 보정 정책만 RL 학습) — "대형 정책에 클러스터 없이 RL을 어떻게 얹는가"의 2025–26 정석 답안. 10GB에 완벽히 맞음.

## T4. 가상 SO-101 파이프라인 — 로봇 팔을 시뮬레이션으로 (2–3 주말)

동료가 말한 그 "허깅페이스 저렴이 로봇"을 **안 사고** 시뮬레이션으로 굴리는 트랙.

- **LeIsaac × LeRobot EnvHub**: Isaac Lab 안에 SO-101 리더/팔로워가 구현돼 있어 **키보드/게임패드 텔레옵 → 데모 수집 → LeRobot 포맷 변환 → ACT/SmolVLA 학습**까지 하드웨어 0원으로 전 과정 가능 (태스크: LiftCube, PickOrange, CleanToyTable 등, 바이매뉴얼 포함). Windows 동작 커뮤니티 가이드 존재 (HackMD asierarranz 가이드)
- **MuJoCo Menagerie `trs_so_arm100`**: 공식 MuJoCo 모델 — 가볍게 돌릴 때
- **NVIDIA 무료 코스 "Train an SO-101 Robot From Sim-to-Real With NVIDIA Isaac"**: Isaac Sim/Lab + LeRobot + 도메인 랜덤라이제이션 커리큘럼. 실기 배포 단계만 빼고 전부 수강 가능. 단 코스의 GR00T 파인튜닝 단계는 10GB 불가 → ACT/SmolVLA로 대체하며 진행 (이 대체 판단 자체가 리포트 소재)
- 주의: Isaac Sim은 **WSL2 불가, 네이티브 Windows로**. 뷰포트가 ~7GB 먹으므로 뷰포트는 GPU1에 (`--/renderer/activeGpu=1`), 씬은 작게

**의미**: 나중에 실기를 사게 되면 같은 코드가 그대로 이식됨. 안 사도 "시뮬 텔레옵 → 데이터셋 → 정책 학습" 스토리는 완성.

## T5. 대차 디지털트윈 + 합성데이터 + sim2real 갭 — 플래그십 (4–8 주말)

NVIDIA의 "팔레트 잭 SDG" 공식 레시피를 대차 도메인으로 이식. **전 과정 무료 도구.**

**Stage A — 대차 에셋 (폰 카메라만 필요)**
1. 대차 1대를 폰으로 150장+ 촬영 (한 바퀴, 확산광)
2. COLMAP(무료, Windows 바이너리) → nerfstudio Splatfacto(gsplat — Windows 휠 제공, MCMC로 가우시안 수 상한 = VRAM 상한 고정)
3. 메시 추출: 2DGS/SuGaR, 또는 사진측량으로 RealityScan 2.0(개인 무료)/Meshroom(오픈소스)
4. Blender(무료): 실측 스케일, 캐스터 휠 분리, revolute 조인트 리깅 → **URDF + USD 자산**
5. (심화) DN-Splatter: ToF depth를 prior로 써서 스플랫 지오메트리 개선 — 보유 데이터와 직결되는 WACV 2025 기법

**Stage B — 합성데이터 공장 + 실데이터 평가**
- 도구 2택 병행 권장:
  - **BlenderProc2** (Windows 네이티브, BOP 공식 SDG 도구): physics drop으로 대차 위 박스 배치, RGB/depth/seg/BOP 어노테이션 자동 + `add_kinect_azure_noise()` 내장
  - **Isaac Sim 4.5 Replicator** (공식 최소사양 RTX 3070 8GB → 스펙 내): 조명·적재·포즈·카메라 랜덤라이즈, SimReady 창고 에셋(팔레트·랙) 무료 제공
- 합성 5–10k장 생성 → 검출·분할 모델 학습(합성 전용) → **실공장 ToF 프레임으로 평가** → DR 축별 ablation으로 sim2real 갭 정량화
- 추가 챕터: 정확한 트윈 vs "digital cousin"(유사 대차·박스 에셋 랜덤) 비교 — ACDC의 "cousin이 twin을 이긴다(90% vs 25%)" 개인 스케일 재현

**Stage C — 시뮬 충실도 계측**
- 재구성 메시에서 실제 카메라 포즈로 depth 렌더링 → ToF 실측과 RMSE/threshold-accuracy
- "시뮬레이션이 좋은지 어떻게 아는가"에 숫자로 답하는 섹션 — 지원자 중 거의 아무도 없음

## T6. 팔레타이징 RL 환경 — 실데이터로 시드한 강화학습 (2–4 주말, VRAM <4GB)

팔레타이징 RL 문헌은 연속 토크 제어가 아니라 **이산 배치 계획**(heightmap 관측 → 배치 셀+방향)이라 네트워크가 작다. 10GB에 가장 친화적이면서 Dexterity/Boston Dynamics Stretch/Amazon이 뛰는 실산업 도메인.

1. T1에서 추출한 **실제 박스 치수·포즈 분포로 환경 시드**
2. heightmap 배치 환경 구현 (안정성 체크는 PyBullet/MuJoCo 짧은 물리 롤아웃)
3. **학습형 action mask + PPO** (arXiv 2404.04772 / 2502.13443 템플릿)
4. 평가: 적재율·안정성 vs deepest-bottom-left 휴리스틱 + **실제 depth map을 평가셋으로 추론**
5. Isaac Lab manager-based 태스크로 포장(ObservationManager/RewardManager 직접 설계)하면 "모션 시뮬레이션 환경 구축" 문구를 문자 그대로 수행한 증거가 됨. 보상 설계 반복 과정을 README에 기록

**심화(선택)**: 인식된 실제 적재 구성을 cuboid로 재구성해 PyBullet에 임포트, 진동 외란에서 붕괴 시뮬레이션 → 기하 휴리스틱(기울기/오버행/무게중심)과 상관 분석 — "인식→물리 시뮬"을 잇는 피지컬 AI 서사.

## T7. ToF 노이즈 캘리브레이션 DR 연구 (2–3 주말; 회사 ToF 카메라 접근 가능할 때)

- 평면 타깃 거리별 촬영 → 실측: σ(거리), flying pixel 비율, 저반사 결손, MPI
- BlenderProc2 `add_kinect_azure_noise()`를 실측 파라미터로 재튜닝
- 증명: 캘리브레이션 노이즈로 학습한 모델이 클린 depth·나이브 가우시안 대비 실데이터 전이 우수
- 2026 발견("과도한 DR은 해롭다")과 연결 — 준논문급 소재. T5에 챕터로 흡수 가능

## 하지 말 것 (시간 절약 체크리스트)

- π0/GR00T/OpenVLA 로컬 파인튜닝 시도 (LoRA도 22.5GB+)
- ManiSkill3 GPU 시뮬을 WSL2에서 시도 (공식: WSL2는 CPU 시뮬만) — 원하면 듀얼부팅 Ubuntu를 초반에 한 번만 결단
