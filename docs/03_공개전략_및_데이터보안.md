# 공개 전략 및 데이터 보안

## ⚠️ 공장 데이터는 회사 자산이다 — 먼저 읽을 것

고객사 현장의 RGB+ToF 이미지는 **업무상 취득한 회사(또는 고객사) 데이터일 가능성이 높다.**

- **원본 이미지·영상을 HF Hub, GitHub, 블로그 등 외부에 업로드하지 않는다** — 명시적 허가 전까지는 절대.
- 현장 식별 정보(회사 로고, 작업자 얼굴, 제품 라벨, 위치 표식)는 내부 분석 단계에서도 마스킹 습관화.
- 이 로드맵의 모든 실험은 **원본 비공개로도 성립한다**:
  - 리포트에는 **집계 수치·그래프·블러 처리된 예시 1~2장**만 사용
  - 코드는 데이터 경로만 분리해 공개 가능 (데이터 없이 재현 구조만 보여줌)
  - T5 합성데이터는 애초에 원본이 아니므로 공개 자유 (단 실장면과 유사한 렌더는 판단 필요)
  - T6 팔레타이징 환경은 "치수 분포 통계"만 쓰므로 원본 노출 없음
- 이직 시 어필도 "실공장 ToF 데이터로 검증했다(수치 제시)"로 충분 — 원본을 보여줄 필요가 없다.
- 가장 깔끔한 경로: 회사에 "익명화·비식별 처리 후 일부 공개" 허가를 서면으로 받는 것. 안 되면 전부 비공개 유지.

## 승인된 공개 범위 (2026-09-02, 데이터 소유자 확인)

- **Depth 기반 시각화 이미지(깊이맵 오버레이·강도 이미지 가공물)는 공개 가능** — 검출/제안 데모 이미지 포함
- **RGB 원본 및 원본에 준하는 이미지는 계속 비공개**
- 원시 .mim/.bmp/.jpg 파일 자체는 여전히 업로드 금지

## 로컬 우선 원칙

- 모든 산출물의 1차 저장소는 `E:\Robot_Sim` (이 저장소).
- 학습 로그: WandB 오프라인 모드(`WANDB_MODE=offline`) 또는 TensorBoard 로컬.
- 라벨링: CVAT 셀프호스팅(Docker) — 클라우드 CVAT 금지.
- 외부 업로드(GitHub/HF/블로그)는 **항목별로 명시 결정** 후에만. 기본값은 비공개.

## 그래도 공개가 필요한 것들 (커리어 관점)

포트폴리오는 결국 남이 봐야 효력이 있다. **회사 데이터가 아닌 것**은 공개가 이득:

| 산출물 | 공개 채널 | 데이터 리스크 |
|---|---|---|
| T2/T3 시뮬 학습 결과 (PushT, gym-hil 등) | GitHub + HF Hub | 없음 (공개 데이터셋) |
| T4 가상 SO-101 데이터셋·정책 | HF Hub (LeRobot v3) | 없음 (시뮬 생성물) |
| T5 대차 USD/URDF 에셋 + SDG 코드 | GitHub | 낮음 (직접 촬영한 대차 1대 — 회사 자산이면 확인) |
| T6 RL 환경 코드 | GitHub | 낮음 (치수 분포는 통계만) |
| T1 리포트 | 블로그(수치·블러 예시만) | **관리 필요** |
| 원본 ToF 이미지 | — | **공개 금지 (허가 전)** |

- 글 하나 = 트랙 하나의 챕터. 시리즈물이 검색 유입·면접 레퍼런스로 가장 효율적
- 회사·현장명은 익명화 ("국내 물류 현장 A")
