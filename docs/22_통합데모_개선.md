# 인식→정책 통합 데모 개선 기록 (v1 → v2)

> 실제 ToF 장면의 적재 상태를 학습된 팔레타이징 PPO에 이식해 "다음 박스 배치 위치"를
> 제안하는 데모. v1 결과에서 NEXT가 기존 박스 위에 걸쳐 보이는 문제를 3가지 원인으로
> 분해하고 각각 수정했다. (`tools/perception_to_policy.py`)

## v1의 문제와 원인

| # | 증상 | 근본 원인 |
|---|---|---|
| 1 | 제안 위치가 실제 슬롯 격자와 어긋남 | 기준 레이아웃 영역(~1170×860mm)을 1100×1100 정사각 그리드에 **늘려 맞춰** X/Y 스케일이 서로 다르게 왜곡됨 |
| 2 | NEXT가 기존 박스 위에 겹쳐 보임 | PPO에겐 박스 위 적재(on-top)도 합법 액션 — 팔레타이징으로는 옳지만 "빈 슬롯 제안" 데모 의도와 충돌 |
| 3 | NEXT 폴리곤 모양이 불규칙 | mm→픽셀 역투영을 최근접 픽셀 탐색으로 해서, 코너가 무효 픽셀(이음새) 근처에서 튐 |

## v2 수정

1. **등척 매핑**: 그리드 셀 = 실측 25mm 고정, 원점만 기준 레이아웃 좌하단으로 — 왜곡 제거
   (PPO가 학습한 좌표계와 물리 스케일이 일치)
2. **빈 슬롯 모드**: `_placement_maps()`의 지지높이가 0인(=노출된 하부층 바닥) 셀만 액션 마스크에
   남김 → 제안이 항상 "픽킹으로 비워진 슬롯"에 위치. on-top 제안이 필요한 시나리오에선 `floor_only=False`
3. **어파인 역투영**: 검출된 박스들의 (mm 중심 ↔ 픽셀 중심) 대응점으로 2×3 어파인을 최소자승
   피팅 → 코너 4점을 안정적으로 투영 (무효 픽셀과 무관, 3박스 이상이면 동작)

## 결과

- 세션 372695(7박스): v1은 박스 6을 가림 → v2는 6번 좌측 빈 슬롯에 정확히 제안
- 세션 380406(3박스): 잔여 박스 열에 인접한 빈 자리 제안 (조밀 적재 성향 = 학습된 정책 특성)
- 시각 구분: 검출=초록, 제안=앰버로 색 분리

## 남은 한계 / 다음 단계

- 어파인은 평면 가정 — 층이 바뀌면(깊이 변화) 대응점도 그 층 것을 써야 함 (현재 세션별 재피팅으로 충족)
- 제안의 정량 평가 없음 → 다음: "실제 작업자가 다음에 놓은 위치"(다음 세션과의 차분)와 제안 일치율 측정
- 3박스 미만 세션에선 어파인 대응점 부족 → 기준 레이아웃 대응점 병용 필요

## v3 — 공정 이해 교정: 이적재(transfer) 방향으로 재설계 (2026-09-02)

**결정적 도메인 입력(데이터 소유자)**: 이 현장은 소스 팔레트의 빈 슬롯에 재적재하는 게 아니라,
**소스(중앙)에서 픽킹해 왼쪽 목적지 영역에 쌓는 이적재 공정**. v2까지 "왼쪽 구조물"로 무시하던
영역이 실은 목적지 스택이었다.

**데이터 검증**: 왼쪽 ROI 상면 깊이가 픽킹 진행에 따라 2722→2477→2313→2230mm로 계단식 상승
(스택 성장), 마지막 3세션에서 3492mm(빈 상태 = 반출됨). 소스 감소 ↔ 목적지 성장의 '질량 보존'
차트(`transfer_conservation.png`)로 공정 전체가 ToF만으로 복원됨.

**v3 구현** (`tools/transfer_place_v3.py`):
1. 목적지 베이스맵 = 빈 상태 3세션의 픽셀별 중앙값 깊이 → 현재 높이 = 베이스 − 현재 깊이
2. 25mm 셀 양자화 + **283mm 층 스냅**(표면 노이즈 제거, 학습 분포와 일치) + 내부 구멍 이웃값 채움
   (무효 픽셀발 벽 핀홀이 지지검사를 전멸시키는 문제 — 디버깅으로 발견)
3. 목적지 밖 셀 = 벽(1500mm)으로 배치 금지 → PPO가 목적지 안에서만 제안
4. 결과: PLACE가 실측 스택 표면 위(현재 높이 1094mm)에 얹힘 — 실제 작업 방향과 일치

**교훈**: 데이터만 보면 공정을 오독할 수 있다 — 도메인 소유자 확인 한 번이 재설계 방향을 바꿨고,
목적지 스택 발견으로 분석 가치가 오히려 커졌다(성장 곡선 = 새 결과물).

## v4 — PICK NEXT: 최소 동선 픽 선택 + 실제 순서로 검증 (사용자 제안)

**제안 배경**: 이적재 사이클타임의 핵심은 배치 위치보다 "다음에 어떤 박스를 집어야
목적지까지 동선이 최소인가". (`tools/pick_next.py`)

**검증 결과 (16개 픽 전이, 세션 차분 = 실제 정답)**:
- 실제 픽의 목적지-거리 순위 **평균 1.69위** (최대 12개 중, 3위 밖 0회) → 실제 시스템이 최소 동선 원칙을 따름
- 단순 최근접 그리디 예측: **정확 일치 50%, top-2 이내 81%**
- 불일치 패턴: 인접 쌍에서 두 번째로 가까운 것 → 가장 가까운 것 순의 로컬 규칙 관찰
  (거리차 10~90mm) — 그리퍼 간섭 회피나 열 단위 스캔 순서로 추정, 다음 분석 대상

**시각화**: PICK 원 + 목적지 화살표(동선 mm) + 실제 픽과의 일치/불일치 표시
