# robotsim_perception 패키지 사용법

> ToF 빈피킹 인식 파이프라인(최상층 → 박스 상면 → 픽 순서)을 순수 numpy/opencv 패키지로 제품화한 것.
> 알고리즘은 `tools/binpick_topface.py`·`tools/binpick_pickpoints.py`·`tools/pick_next.py` 와 동일하며,
> 실측 30세션에서 **148/148 박스 완전 일치**(치수·면적·깊이 동일)를 파리티 테스트로 보증한다.
> 코드: `robotsim_perception/` · 테스트: `tests/` · 설정: `pyproject.toml`

## 1. 설치

의존성: `numpy>=1.24`, `opencv-python>=4.8`, `tifffile` (.mim 로드용). Python 3.9+.
numpy 1.26/opencv 4.10 (anaconda) 과 numpy 2.2/opencv 5.0 (.venv) 양쪽에서 동작 확인.

```bash
# (a) 설치 없이: 레포 루트를 PYTHONPATH 에
set PYTHONPATH=E:\Robot_Sim
python -m robotsim_perception version

# (b) 편집 가능 설치 (.venv 예시, 오프라인이면 --no-build-isolation)
E:\Robot_Sim\.venv\Scripts\python.exe -m pip install -e E:\Robot_Sim --no-build-isolation
robotsim-perception version        # 콘솔 스크립트도 등록됨
```

## 2. CLI

```bash
python -m robotsim_perception run <session_dir> --json out.json --overlay out.png
# 옵션
#   --sku L W H          박스 SKU mm (기본 293 219 283)
#   --sku-tol 0.5        L/W 가 SKU 대비 ±50% 밖인 후보 제거 (기본: 끔 = tools 와 동일 검출 집합)
#   --dest X Y           목적지 스택 중심, 카메라 좌표 mm (기본 -1191.4 -38.3; 음수 그대로 입력)
#   --col-tol 80         열 스캔 규칙의 열 허용 폭 mm
#   --tol 40             최상층 깊이 허용 ±mm     --min-area 700  최소 요소 픽셀
#   --min-confidence 0.6 신뢰도 미만 박스 제거    --quiet
```

`<session_dir>` 은 `2_tof_X.mim 3_tof_Y.mim 4_tof_D.mim 5_tof_I.mim` (640×480 float32, mm) 을 담은 폴더.
콘솔 출력은 ASCII 만 사용(cp949 콘솔 호환). 실측 첫 세션 예:

```
top layer : 2973.0 mm
boxes     : 12
  [0] L302 x W216 mm  z=2972  tilt=1.2deg  conf=0.83  center=(145,-359)
  ...
pick plan : 10 -> 2 -> 7 -> 11 -> 3 -> 6 -> 8 -> 0 -> 4 -> 9 -> 1 -> 5  (first dist 798 mm to dest)
latency   : 116.3 ms  (load 38.5, top 6.5, detect 109.6, plan 0.13)
```

## 3. Python API

```python
from robotsim_perception import load_frame, detect_top_layer, detect_boxes, pick_plan, run_session, render_overlay

frame = load_frame(r"H:\...\126013011364085")      # Frame(X, Y, D, I, valid, source)
top   = detect_top_layer(frame)                     # TopLayer(depth_mm, mask, tol_mm, n_px); top.ok
boxes = detect_boxes(frame, sku=(293, 219, 283))    # list[Box]
plan  = pick_plan(boxes, dest_xy_mm=(-1191.4, -38.3))   # list[PickStep], 열 스캔 순서

res = run_session(session_dir)                       # 위 셋을 한 번에 + 지연 측정
res.to_json("out.json"); render_overlay(frame, res, "out.png")

# 메모리 프레임 (예: 합성)
from robotsim_perception.synthetic import SynthBox, make_frame
fr = make_frame([SynthBox((-250, 0), depth_mm=1500), SynthBox((250, 100), depth_mm=1500, yaw_deg=90)], noise_mm=3)
```

| 데이터클래스 | 필드 |
|---|---|
| `Frame` | `X Y D I` float32 (H,W) mm · `valid` bool (센티넬 D=16383.75/0, \|X\|,\|Y\|=8191.75, 비유한값 제외) · `source` |
| `Box` | `id center_mm(X,Y,Z) dims_mm(L,W) tilt_deg normal rect_px confidence depth_mm area_px center_px plane_rms_mm fill` |
| `PickStep` | `order box_id center_mm dist_mm anchor_id column_size reason` |
| `Result` | `frame top_layer boxes plan sku dest_xy_mm col_tol_mm latency_ms latency_breakdown_ms source` |

- `normal` 은 카메라 쪽(-Z)을 향하는 단위 법선 → 석션 접근 벡터 = `-normal`. `tilt_deg` = 광축 대비 기울기.
- `confidence`(0..1, 휴리스틱) = 0.5·SKU치수일치(오차 15%에서 0) + 0.25·채움률(0.5→0, 1.0→1) + 0.25·평면RMS(25mm에서 0).
  실측 148박스 평균 0.82(min 0.30). `sku=None` 이면 치수 항 제외.
- 픽 순서 규칙(`tools/pick_next.py`, 실제 순서와 81% 일치): 목적지 최근접 박스가 속한 열(|dx|<80mm)에서
  목적지에서 **가장 먼** 박스부터. 남은 박스가 없을 때까지 반복해 전체 순서를 만든다.

## 4. JSON 스키마 (`schema_version` = "1.0")

| 키 | 타입 | 설명 |
|---|---|---|
| `schema_version` / `package_version` | str | "1.0" / 패키지 버전 |
| `timestamp`, `source` | str | 생성 시각(ISO), 세션 경로 |
| `frame` | {shape[2], valid_px, valid_frac} | 입력 프레임 요약 |
| `sku_mm` | [L,W,H] \| null | 사용한 SKU |
| `top_layer` | {depth_mm \| null, tol_mm, n_px} | 최상층 (탐색 실패 시 depth_mm=null, boxes=[]) |
| `n_boxes`, `boxes[]` | int, list | 박스: `id center_mm[3] dims_mm[2] tilt_deg normal[3] rect_px{center[2],size[2],angle} confidence depth_mm area_px center_px[2] plane_rms_mm fill` |
| `pick_plan` | {rule, dest_xy_mm[2], col_tol_mm, steps[]} | steps: `order box_id center_mm[3] dist_mm anchor_id column_size reason` |
| `latency_ms` | float | 인식 연산 시간 = 최상층+검출+계획 (디스크 로드 제외) |
| `latency_breakdown_ms` | {top_layer, detect_boxes, pick_plan, load?, total} | 단계별 (CLI/run_session 은 load 포함) |

모든 값은 순수 Python 타입(JSON 직렬화 가능). 좌표는 ToF 카메라 좌표계 mm, 픽셀은 640×480 기준.

## 5. 검증 결과 (2026-09-03)

- **파리티**: 실측 30세션 148박스 — `tools/binpick_topface.detect_boxes` 와 검출 수·치수·면적·깊이 완전 일치 (L 293.0±9.2 / W 218.8±9.9 mm 재현).
- **지연**: 실측 프레임 인식 연산 평균 51.8 ms, 최대 102 ms (anaconda python, CPU); .mim 4채널 로드 ~40 ms 별도.
- **테스트**: `D:\anaconda\python.exe -m pytest tests -q` → **27 passed in 5.24s** (합성 13 + 파이프라인/CLI 6 + 픽 계획 5 + 실측 통합 3; 실측 3개는 `BINPICK_DIR` 없으면 skip).
  - 합성 2박스(1500mm, ~98×73px): 치수 오차 < 5% (실측 -2.7%/-4.1%), 8mm 노이즈·5° 기울기(측정 5.0°)에서도 2개 유지
  - 실측 거리(2970mm, ~49×37px) 2×3 격자 6개, 맞닿은 박스는 강도(I) 체커보드 에지로 6개 분리
  - 센티넬 블록·D=0·NaN/inf 는 무효 처리, 완전 무효/0/NaN 프레임 → 박스 0, 박스 없는 평평한 바닥 → `sku_tol` 로 제거
  - JSON 스키마·.mim 라운드트립·CLI(subprocess)·오버레이 PNG

## 6. 알려진 한계

- **경계 침식 편향**: 그래디언트·강도 에지 필터가 상면 경계 ~2–3px 를 깎아 이상적인 합성 에지에서 치수가 과소
  (49px 박스 -3~-7%, 98px 박스 -3~-4%). `tools/` 와 동일한 동작이며 기존 실측 기준값(293/219)도 같은 편향을 포함하므로
  보정하지 않았다(파리티 우선). 절대 치수가 필요하면 실물 SKU 로 캘리브레이션 필요.
- **최상층 가정**: 중앙 ROI 깊이 히스토그램의 최대 피크를 최상층으로 잡으므로, 평평한 바닥이 ROI 를 지배하는 장면(박스 1–2개, 먼 거리)에서는
  바닥이 최상층으로 잡힐 수 있다. 합성 테스트는 바닥을 기울여(여러 빈에 분산) 이 조건을 피했다.
  **실측 확인(2026-09-04)**: 30세션 RGB 대조 결과 실제 박스는 167개이고 이 패키지(=v1)는 148개(88.6%)를 잡는다. 놓친 19개 =
  층 말미 잔여 박스 1~2개(피크가 바닥/티어시트로 전환, 4프레임 6박스) + 2층 4×3 격자 중앙 2개(강도 에지 절단 실패로 병합, 7프레임 13박스).
  `tools/binpick_topface.detect_boxes_v2`(격자 결손 보완 + 다른 피크 층 재시도)가 167/167 을 회수하며(226 ms/프레임, 빈 프레임 오검출 0),
  패키지 이식은 다음 단계다. 그때까지 `detect_boxes` 결과의 박스 수는 하한으로 봐야 한다.
- 맞닿은 박스의 분리는 강도(I) 에지에 의존 — 강도 차가 없는 이음새는 병합될 수 있다(`sku_tol`·`confidence` 로 걸러짐).
- `--dest` 기본값은 현장 세션의 목적지 스택 좌표(`explore/pickpoints/pick_order_eval.json`) — 다른 현장에서는 반드시 지정.
